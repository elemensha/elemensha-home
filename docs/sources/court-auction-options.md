# 법원경매 물건 데이터 수집 경로 조사

조사일: 2026-08-24
목적: 서울·경기 부동산 물건 알림 앱에 법원경매 데이터를 넣을 수 있는지, 넣는다면 비용이 얼마인지 판단.
전제: 온비드 공매 + 국토부 실거래가는 공공데이터포털 무료 OpenAPI로 이미 해결됨.

---

## 1. 무료·공식 경로

### 결론: **없음.** 법원경매 물건을 조회하는 공식 무료 API는 존재하지 않는다.

#### 1-1. 대법원 법원경매정보(courtauction.go.kr)

API도, 데이터 개방 페이지도 제공하지 않는다. 사이트는 사람이 브라우저로 조회하는 웹 화면만 제공한다.
- https://www.courtauction.go.kr/

이건 추측이 아니라 **대법원이 공식적으로 답변한 기록**이 있다. 공공데이터 분쟁조정위원회 사례 3건이 전부 대법원 경매 데이터를 대상으로 했고, 3건 모두 조정불성립으로 끝났다.

**사례 2015-009 「법원 경매정보 OPEN API」** (피신청기관: 대법원)
- 대법원 답변: 신청한 데이터가 현재 OPEN API 형태로 구축되어 있지 않으며, 공공데이터법 제26조 제3항에 의하여 공공기관은 이용자의 요청에 따라 추가로 공공데이터를 생성·가공·요약·발췌하여 제공할 의무를 지지 않는다.
- 조정위원회는 향후 OPEN API 구축을 *권고*했으나 강제력 없음. 결과 조정불성립.
- 출처: https://www.data.go.kr/odmc/trublMdat/mdatCase/board.do?id=45

**사례 2015-002 「부동산 경매 낙찰데이터 원시데이터(2005~2014)」** (피신청기관: 대법원)
- 조정안: 2013년 서울지역 낙찰건을 사건번호·감정평가액·경매기일·최저매각가격·기일결과·매각액 항목의 raw data로 제공
- 대법원이 수락 거부. 조정불성립.
- 출처: https://www.data.go.kr/odmc/trublMdat/mdatCase/board.do?id=45

**사례 2016-007 「천안시·아산시 경매정보(2004~2015)」** (피신청기관: 대법원)
- 대법원 거부 논거가 핵심이다: "법원 경매관련 정보의 경우 민사집행법 제106조에 의하여 공고기간(입찰기일 1주일 전) 동안 공고하고 있으나, **공고기간 이후에는 소송기록으로 취급**되어" 공공데이터법 제4조의 예외에 해당한다.
- 조정불성립.
- 출처: https://www.data.go.kr/odmc/trublMdat/mdatCase/board.do?id=69

> **이 논거가 중요한 이유**: 대법원은 경매 물건 정보를 "공공데이터"가 아니라 "소송기록"으로 본다. 공고기간(매각기일 1주 전부터)에만 공개 의무가 있고, 그 외에는 개방 의무가 없다는 입장이다. 즉 정책적 게으름이 아니라 **법리적 입장**이므로, 가까운 시일 내에 무료 API가 열릴 가능성은 낮다.

#### 1-2. 공공데이터포털(data.go.kr)

"법원경매" 검색 결과에 대법원 제공 오픈API는 없다. 검색되는 것은 전부 **한국감정평가사협회**가 올린 통계 파일/링크데이터다.
- 「연도별 법원경매 통계」, 「법원경매 지역별 매각 통계」, 「법원경매 용도별 매각 통계」, 「법원별 경매평가 아파트호수」, 「법원별 경매평가 자동차수」 등
- 전부 **집계 통계**이지 개별 물건 목록이 아니다. 물건 알림 앱에는 쓸 수 없다.
- 출처: https://www.data.go.kr/tcs/dss/selectDataSetList.do?keyword=법원경매

부분적으로 관련된 것 하나:
- 「한국주택금융공사_법적절차진행이력정보」 — 관할법원명, 경매계명, 경매개시결정일자, 취하일자, 배당일자 포함. 다만 **HF 보증 채권 건에 한정된 과거 파일 데이터**(2005-05-31 기준)이고 물건 주소·감정가가 없다. 알림용으로 무의미.
- 출처: https://www.data.go.kr/data/15072797/fileData.do

#### 1-3. 법원 등기정보광장(data.iros.go.kr) Open API

**경매 물건 데이터는 포함되지 않는다.** 등기 통계(소유권이전, 근저당권 설정/말소, 확정일자, 법인등기 등) 중심이다. 사이트 자체가 법원경매정보를 "관련 사이트"로 외부 링크 걸어두고 있어 별도 시스템임이 드러난다.
- 신청 절차: 회원가입 → Open API 신청서 → 승인 심사 → 테스트 환경 개발 → 서비스 이용 신청 → 관리자 심사 → 이용계약 체결 (9단계)
- **이용 한도: 월 1,000건, 초과 시 자동 차단**
- 출처: https://data.iros.go.kr/rp/oa/openOapiIntro.do

경매 물건에는 못 쓰지만, 만약 특정 물건의 등기 변동을 추적하고 싶다면 별도로 검토할 가치는 있다. 다만 월 1,000건 한도는 알림 서비스에 매우 빡빡하다.

#### 1-4. 사법정보공유포털(openapi.scourt.go.kr)

제공 API는 **사건기본정보 API**와 **사건진행내역 API** 두 가지. 경매 물건 목록 API는 없다.
- 오픈API는 "추후 업데이트 예정" 상태로 남아 있고, 실질적으로 이용 가능한 것은 **연계 API**뿐이다.
- 연계 API는 공개 신청 창구가 없고 법원행정처 API 담당자(publicapi@scourt.go.kr)에게 개별 문의해야 한다. 사실상 기관 대 기관 연계용.
- 출처: https://openapi.scourt.go.kr/kgso201m01.do , https://openapi.scourt.go.kr/kgso202m01.do , https://openapi.scourt.go.kr/kgso301m01.do

**섹션 1 요약**: 무료 공식 경로 = 없음. 대법원은 경매 정보를 소송기록으로 규정해 개방을 거부해왔고, 이 입장은 2015년부터 2016년까지 분쟁조정에서 일관되게 유지됐다.

## 2. 유료 중계 API 요금 비교

> **요금 표기 원칙**: 공개된 가격표에서 확인한 숫자만 적었다. 확인 못 한 항목은 "공개 정보 없음 — 영업문의 필요"로 남겼고 추정치를 넣지 않았다.

### 2-1. CODEF (코드에프) — (주)헥토데이터

- 요금 페이지: https://codef.io/pricing
- 경매 API 문서: https://developer.codef.io/products/public/each/ck/auction-events

**요금 (공개된 것 전부)**

| 플랜 | 가격 | 내용 |
|---|---|---|
| 샌드박스 | **무료** | 테스트 데이터만. 실데이터 아님 |
| 데모버전 | **무료** | 실제 데이터, **1개월간 하루 100회** 호출. (일부 제휴 API 제외) |
| 정식버전 | **"별도 상담"** — 공개 금액 없음 | 호출 무제한, 호출 건수에 따라 과금 |

- 과금 방식: **호출 건당 후불**. "데이터를 호출하고 이에 대한 응답이 있는 경우 1건으로 측정됩니다. 유효한 호출 건수에 대해서만 과금됩니다. (무효, 오류 건수 제외)"

- 최소 계약: 정식버전 FAQ에 "**별도 계약 없이** 필요한 API를 즉시 추가하여 사용할 수 있습니다"라고 명시. 약정 기간 조건은 공개돼 있지 않음.
- **건당 단가는 끝내 공개돼 있지 않다.** 과거 있던 요금 계산기는 종료됐다:
  > "가격정책 변경에 따라 요금 계산기 서비스를 종료합니다. 요금과 관련해 궁금하신 사항은 아래 채널로 문의해 주세요."
  > hd_support@hecto.co.kr / 02-6953-0257
  > — https://codef.io/pricing/calculator
- 개인 개발자 가능 여부: 요금 페이지가 정식버전 대상을 "안정적으로 이용하고 싶은 스타트업, **예비 창업자**, 중견/소기업"으로 표기. 데모버전은 즉시 무료 가입 가능. 정식버전 결제가 "계좌 혹은 카드" 자동결제라 개인 명의 가능성은 있으나 **사업자등록 요구 여부는 공개 문서에 명시 없음 — 영업문의 필요**.

**제공 데이터 범위 — 여기가 함정이다**

CODEF 대법원 카테고리에서 경매 관련 API는 **「경매사건검색」 단 하나**다 (전체 목록 확인: https://developer.codef.io/products/public/each/ck/introduction — 나머지는 나의사건검색, 회생파산, 등기부등본류).

그리고 이 API의 **입력 파라미터가 전부 필수**다:

| 파라미터 | 설명 | 필수 |
|---|---|---|
| `organization` | 기관코드 (고정 `0004`) | O |
| `courtName` | 법원명 | O |
| `caseNumberYear` | 사건번호 년도 (YYYY) | O |
| `caseNumberNumber` | 사건번호 번호 | O |

> **즉 사건번호를 이미 알고 있어야 조회가 된다.** "서울·경기 지역의 새 물건을 목록으로 받아오는" 검색 API가 아니다. 알림 앱의 핵심인 *신규 물건 발견*을 이 API로는 할 수 없다. 사건번호를 어디선가 따로 확보한 뒤 상세를 채우는 용도다.

반면 **사건번호만 알면 나오는 정보는 상당히 깊다**:
- 물건내역(`resProductList`): 물건번호, 물건용도, **감정평가액**, **최저매각가격**, 물건상태, 최근입찰결과, 물건비고
- 상세내역(`resDetailList`): 소재지 주소, 목록구분(토지/건물), 제시외
- 기일내용(`resDateList`): **매각기일**, 매각결정기일, 기일장소, 최저매각가격, 기일결과
- 당사자내용(`resInvolvedPersonList`): 채권자·임차인 등 **당사자 구분과 성명**
- 배당요구종기내역, 항고내역, 관련사건, 송달내역, 문건처리내역
- 사건 기본: 사건번호, 사건명(예: 부동산강제경매), 청구금액, 개시결정일, 종국결과, 담당 경매계 연락처

**없는 것**: 감정평가서 원본(PDF/이미지), 매각물건명세서, 현황조사서, 등기부 자체, 가공된 권리분석 의견. 등기부는 별도 상품(「부동산등기부등본 열람/발급」)이며 열람 수수료가 별도로 붙는다.

### 2-2. 하이픈(HYPHEN) — 「부동산 법원경매 정보(경매다)」 ★ 요금이 공개된 유일한 곳

- 상품 페이지: https://hyphen.im/product/view?seq=207
- 개발가이드: https://hyphen.im/product-api/view?seq=207

**요금 (사이트에 실제로 게시된 숫자)**

| 항목 | TR슬림 | TR시그니처 |
|---|---|---|
| 멤버십 | **월 10만원** | 기본 제공 |
| 월 기본료 | — | **월 30만원~** |
| 결제수단 | 비즈머니(선불충전) | 계좌이체(후불청구) |
| 계약서 | **미작성 (X)** | **작성 필요 (O)** |
| 과금 | TR **건 별 정상요금** | 상품별 기본 건 수, 소진 시 협의 |
| 테스트베드 | O | O |
| 사용량 컨설팅 | X | O |

- 포지셔닝: TR슬림 = "서비스 구축중이거나 API사용량이 적은 기업", TR시그니처 = "API 사용량이 많은 기업... 컨설턴트와 계약 후 사용 가능"
- **건당 TR 단가는 비공개.** 상품 페이지의 API 테이블에 요금 열이 있으나 비로그인 상태에서는 값이 비어 있다. → **공개 정보 없음, 영업문의 필요**
- 무료 체험: 이 상품에는 별도 무료 건수 안내가 없다. 같은 마켓의 「부동산 시세 추정(랜드바이저)」은 10건 무료 테스트를 명시하지만 경매다는 그런 문구가 없고, 대신 이렇게 적혀 있다: "※ 해당 상품은 **제휴 상품**으로 보너스 캐시를 이용하실 수 없습니다."
- 개인 개발자 가능 여부: 요금제 설명이 일관되게 "**기업**"을 대상으로 쓰여 있고, 제휴/원문서 상품은 "배정된 전문 컨설턴트를 통해 상품 계약을 생성한 후 이용"하도록 안내된다. **개인 명의 계약 가능 여부는 공개 문서에 명시 없음 — 영업문의 필요.** 다만 TR슬림은 "계약서 미작성 + 선불 비즈머니"라서 진입 장벽은 CODEF 정식버전보다 낮아 보인다.

**제공 데이터 범위 — CODEF보다 이 앱에 훨씬 잘 맞는다**

API 11개를 제공하며, 그중 **검색 API 3종이 지역·용도 필터로 물건 목록을 뽑아준다**:

- 코드 조회 5종: 현황코드(신건/유찰/기각/변경/정지/취하), **시도코드**, **구군코드**, **동코드**, 법원별코드, 용도별코드(아파트/다세대/주택 등), 소재지조회
- **경매신건검색** / **경매진행물건검색** / **용도별물건검색** — 반환 항목:
  경매번호, 사건번호, 법원코드, 물건번호, **매각기일**, **감정가**, **최저가**, 물건용도코드, 진행상태, **건물면적**, **토지면적**, **유찰수**, 대표소재지, 지번주소, 담당계, **낙찰가**, 용도
- **경매사건상세보기** (검색 API로 얻은 경매번호를 입력) — 반환 항목이 매우 넓다:

## 3. 스크래핑의 법적·기술적 현실

> 사실 조사만 했다. 우회 기법이나 수집 코드는 다루지 않는다.

### 3-1. 이용약관 — 자동화 수집 금지 조항은 "있다, 다만 간접적으로"

출처: https://www.courtauction.go.kr/pgj/index.on → 하단 「이용약관」 (WebSquare 모달, 별도 URL 없음). 정식 명칭 「법원경매정보 이용약관」, 당사자는 법원행정처('갑')와 이용자('을').

**핵심 조항 — 제15조 ('을'의 의무)** (원문 그대로 인용)

> **제15조 (‘을’의 의무)**
> ‘을’은 다음 각 호의 행위를 하여서는 아니 된다.
> 1. ‘갑’이 관리하는 컴퓨터에 부정하게 접속하는 방법 등을 이용하여 법원경매정보 서비스를 방해하거나, 법원경매정보 서비스의 이용에 제공되고 있는 설비에 손상을 주는 행위
> 2. **부정한 목적으로 또는 ‘갑’의 동의 없이 법원경매정보 홈페이지에서 제공하는 서비스의 내용을 가공하거나 입찰참가 외의 영리목적으로 서비스를 이용하는 행위**
> 3. 제공받은 법원경매정보 서비스 내용 또는 형식의 위·변조와 그 밖의 부정행위
> 4. ‘갑’ 및 기타 제3자의 지적재산권을 침해하는 행위

> **"크롤링 금지"라는 표현은 약관 어디에도 없다.** 대신 제15조 2호가 결정적이다. ①법원행정처의 동의 없이 서비스 내용을 **가공**하는 것, ②**입찰참가 외의 영리목적**으로 서비스를 이용하는 것을 각각 금지한다. 경매 데이터를 긁어와 가공해서 알림 앱으로 서비스하는 행위는 이 두 가지에 정면으로 걸린다. 수동으로 하든 자동으로 하든 마찬가지다 — 금지의 기준이 *수집 방식*이 아니라 *가공과 영리 이용*이기 때문이다.

**보조 조항 — 「이용시 유의사항」** (같은 푸터)

> "CourtAuction(법원경매정보)의 안정적인 운영을 위하여 법원경매정보 홈페이지의 **비정상적 접근 또는 비정상적인 다량 조회가 확인되는 경우 해당 IP Address의 접속이 차단될 수 있습니다.**"

이게 자동화 수집에 가장 가까운 명시적 언급이며, 동시에 **기술적 차단이 실제로 운영되고 있다는 고지**다.

**약관의 인적 범위 (중요한 미묘함)**
- 제2조 ②: "'이용자'라 함은 '갑'에게 **개인정보를 제공하여 회원등록을 한 자**"
- 제3조: "이 약관은 법원경매정보 홈페이지를 통하여 공시되고 **'을'이 동의함으로써 효력을 발생**한다."

→ 문언상 제15조의 의무는 **회원**에게 부과된다. 비회원 열람에는 약관이 계약으로 성립했다고 보기 어렵다는 해석 여지가 있다. 다만 이는 약관 위반 책임을 면할 여지일 뿐, 아래 저작권·부정경쟁방지법 책임과는 별개다.

- **SPA 구조**: 화면 정의가 서버의 XML 파일로 존재 (`/pgj/ui/pgj100/PGJ151F00.xml` = 물건상세검색, `PGJ159M00.xml` = 경매사건검색). 브라우저 URL은 `index.on?w2xPath=...` 형태로 화면만 바뀐다 → **HTML 파싱형 스크래핑이 통하지 않는다.**
- **데이터 통신**: 화면 렌더 후 `POST /pgj/{모듈}/{액션}.on` 형태의 XHR로 JSON을 받는다. 실제 관측된 엔드포인트: `pgj002/selectCortOfcLst.on`(법원목록), `pgj002/selectAdongSdLst.on`(시도), `pgj002/selectRdnmAddr.on`(도로명주소), `pgj111/selectRletYrDspslStats.on`(연도별매각통계) 등
- **세션**: 쿠키 `WMONID`(WebSquare 모니터링 ID), `cortAuctnLgnMbr`, `lastAccess`. 대부분의 조회는 비로그인으로 가능하다.
- **CAPTCHA**: 메인 및 검색 진입 화면의 DOM에서 캡차/보안문자 요소가 **확인되지 않았다.** 다만 3-1의 "비정상적인 다량 조회 시 IP 차단" 고지가 있으므로 **속도 기반 차단이 캡차를 대체하는 구조**로 보인다.
- **이미지**: 감정평가서·현황조사서·매각물건명세서는 텍스트가 아니라 **문서 이미지/PDF로 제공**되며, 조회 기간도 제한된다(3-6 참조). 텍스트 추출에는 OCR이 필요하다.

### 3-6. 데이터 가용 기간 — 알림 앱 설계에 치명적인 제약

「이용시 유의사항」의 부동산 정보 항목:

| 항목 | 공개 시점 |
|---|---|
| 매각공고 | **매각기일 14일 전부터** 게시 |
| 물건상세검색 | 현재 날짜 이후 기일만, **2주 후 매각기일까지만** 검색 가능 |
| 매각물건명세서 | 매각기일 **1주 전**부터 매각기일까지 |
| 현황조사서·감정평가서 | 매각기일 **2주 전**부터 매각기일까지 |
| 매각결과 | 매각기일 다음날부터 **7일간만** 제공 |

> **즉 공식 사이트는 언제나 "앞으로 2주" 창만 보여준다.** 과거 낙찰 이력은 7일 지나면 사라진다. 유료 업체들이 존재하는 실질적 이유가 이것이다 — 그들은 매일 수집해 **자체 히스토리 DB를 축적**하고, 그 축적분이 상품 가치다. 사이트를 긁는다고 해서 하루아침에 같은 데이터를 갖게 되지 않는다.

### 3-7. 개인 본인 용도 vs 서비스 재배포

| | 개인이 본인 입찰 목적으로 조회 | 앱 서비스로 재배포 |
|---|---|---|
| 약관 제15조 2호 | **문제 없음.** 조항이 금지하는 건 "**입찰참가 외의** 영리목적" — 본인 입찰 준비는 정확히 허용 대상 | **정면 위반.** 가공 + 입찰참가 외 영리목적 둘 다 해당 |
| 저작권 (제24조의2) | 자유이용, 출처표시 | 자유이용이지만 법원이 저작재산권 전부 보유한 것에 한정 |
| DB제작자 권리 (제93조) | 개인 소량 이용은 "상당한 부분의 복제"에 해당하기 어려움 | 지역 전체를 반복 수집·축적하면 **상당한 부분의 복제·전송**에 해당할 소지 (잡코리아 판례) |
| 부정경쟁방지법 | 해당 없음 | 타인의 상당한 투자·노력의 성과 무단 사용 쟁점 발생 가능 |
| 기술적 차단 | 정상 조회 속도면 무관 | **다량 조회 시 IP 차단 명시** — 서비스 안정성 자체가 성립 안 됨 |
| 실무 결론 | **가능** | **하지 마라** |

> 개인이 자기 물건 찾으려고 브라우저 자동화로 몇 건 조회하는 것과, 서울·경기 전역을 매일 훑어 사용자에게 푸시하는 것은 **법적으로 완전히 다른 행위**다. 후자는 약관 위반이 명확하고, IP 차단으로 서비스 신뢰성도 담보되지 않는다. **알림 앱의 데이터 소스로 courtauction.go.kr 스크래핑은 선택지가 아니다.**

### 4-4. 종합 판단 — 법원경매를 빼면 무엇을 잃는가

**잃는 것**
1. **물량의 대부분.** 주거용 부동산 알림 앱에서 온비드만 쓰면 물건의 8할 이상을 못 본다. 연 12만 건 vs 3만 건(그마저도 자동차·동산 포함)
2. **수도권 아파트 딜플로우 자체.** 서울 아파트 경매만 월 150~180건이고 낙찰가율 100% 초과의 활황장이다. 여기가 사용자 수요가 몰리는 곳이다
3. **제품의 정체성.** "부동산 물건 알림"인데 경매가 빠지면 사용자 입장에서는 반쪽짜리다. 경쟁 앱(탱크옥션·마이옥션·지지옥션)은 전부 경공매를 함께 다룬다

**덜 잃는 것 / 완화 요인**
1. 법원 공식 **메일링 서비스**가 무료로 존재한다. 앱이 못 하는 것을 사용자가 직접 설정하면 이메일로 받을 수 있다 → 앱에서 "법원 알림 설정하는 법" 안내로 부분 대체 가능
2. 실거래가·공매는 이미 무료 OpenAPI로 확보돼 있고, **이 둘만으로도 성립하는 제품**이다 (시세 추적 + 공매 알림)
3. 법원경매는 **어차피 공짜로 못 넣는다.** 무료 공식 API 없음(섹션 1), 스크래핑은 약관 위반(섹션 3) → 넣으려면 **월 10만원 이상의 고정비**가 확정된다(섹션 2)

### 네 가지 질문에 대한 답

**1. 무료 공식 경로가 있는가 → 없다.**
대법원은 경매 정보를 "공공데이터"가 아니라 "**소송기록**"으로 규정한다. 공고기간(매각기일 1주 전) 외에는 개방 의무가 없다는 입장이며, 2015~2016년 공공데이터 분쟁조정 3건에서 일관되게 거부해 전부 조정불성립으로 끝났다. 등기정보광장·사법정보공유포털에도 경매 물건 데이터는 없다. **정책적 게으름이 아니라 법리적 입장이므로 곧 열릴 가능성은 낮다.**

**2. 유료 옵션 → 실질적으로 하이픈 하나뿐이다.**

| | 하이픈(경매다) | CODEF | 쿠콘 |
|---|---|---|---|
| 공개 금액 | **TR슬림 월 10만원 / TR시그니처 월 30만원~** (건당 단가 비공개) | **비공개** ("별도 상담", 요금계산기 종료) | **비공개** |
| 지역으로 신규 물건 검색 | **가능** | **불가** (사건번호 필수) | 미확인 |
| 권리분석 | 제공 (말소기준권리·예상배당·예상명도비용) | 없음 | 미확인 |
| 무료 체험 | 명시 없음 | **1개월 일 100회 실데이터** | 미확인 |

CODEF는 무료 체험이 후하지만 **사건번호를 이미 알아야 조회되므로 알림 앱의 "발견" 단계를 못 채운다.** BidQ는 조달 입찰 플랫폼이라 애초에 해당 없다. 지지옥션·옥션원·마이옥션 등은 B2C 구독 서비스로 공개 API가 없다.
→ **하이픈만이 요구사항을 충족하며, 최소 월 10만원 고정비가 확정된다. 건당 단가는 반드시 영업문의로 확인해야 한다** (하이픈 온라인문의 / 헥토데이터 hd_support@hecto.co.kr, 02-6953-0257).

**3. 약관상 스크래핑 → 하면 안 된다.**
「법원경매정보 이용약관」 **제15조 2호**가 결정적이다:
> "부정한 목적으로 또는 '갑'의 동의 없이 법원경매정보 홈페이지에서 제공하는 서비스의 내용을 **가공**하거나 **입찰참가 외의 영리목적**으로 서비스를 이용하는 행위"

"크롤링 금지"라는 단어는 없지만, 금지 기준이 *수집 방식*이 아니라 *가공과 영리 이용*이라 **앱 서비스로 재배포하는 행위가 정확히 걸린다.** 「이용시 유의사항」은 "비정상적인 다량 조회 시 IP 차단"을 명시하며 실제로 운영 중이다. robots.txt는 없다(404). 판례상 크롤링 자체는 형사 무죄지만(야놀자 v 여기어때, 대법원 2022), **재배포는 DB제작자 권리 침해로 민사에서 진다**(잡코리아 v 사람인). 게다가 사이트는 항상 "앞으로 2주" 창만 보여주고 매각결과는 7일 뒤 사라지므로, **긁어도 유료 업체 수준의 히스토리 DB는 만들어지지 않는다.**
→ 개인이 본인 입찰 준비로 조회하는 것은 약관상 명시적으로 허용 범위(제15조 2호는 "입찰참가 **외의**" 영리목적을 금지). **서비스 재배포는 선택지가 아니다.**

**4. 법원경매를 빼면 → 주거용 물건의 8할 이상을 잃는다.**
법원경매 연 12.1만 건(주거시설 10.9만 건) vs 온비드 공매 연 3만 건(자동차·동산 포함 전체). 서울 아파트만 월 150~180건. 공매는 인도명령이 없어 명도에 5~6개월이 걸리므로 일반 개인 사용자에게는 오히려 더 어렵고, 대체재로 기능하지 못한다.
**다만 완화 요인이 하나 있다**: 대법원이 **무료 메일링 서비스**를 공식 제공한다(약관 제6조 ①7 — 저장한 검색조건에 맞는 물건을 이메일 발송). 앱이 이를 재판매할 수는 없지만, 사용자에게 설정 방법을 안내하는 것으로 부분 대체가 가능하다.

### 실무 권고

1. **지금 당장은 법원경매를 넣지 마라.** 무료 경로가 없고, 스크래핑은 약관 위반이며, 유료는 월 10만원부터 시작한다. 온비드 공매 + 국토부 실거래가로 먼저 제품을 검증하라.
2. **앱 안에 "법원경매 알림은 대법원 사이트에서 무료로 설정하세요" 안내를 넣어라.** 합법이고, 비용이 0원이며, 사용자에게 실제로 유용하다.
3. **유료화 판단은 사용자 수가 붙은 뒤에 하라.** 그때 하이픈에 영업문의해 **건당 TR 단가**를 받아라. 월 10만원 고정비는 사용자 수와 무관하게 나가므로, 손익분기는 전적으로 건당 단가에 달려 있다.
4. **CODEF는 보조 용도로만 검토하라.** 사건번호를 확보한 뒤 상세를 채우는 데는 쓸 수 있고, 실데이터 1개월 무료 체험이 있어 데이터 품질 검증에는 유용하다.

### 확인하지 못한 것 (모두 영업문의 필요)

- 하이픈 경매다의 **건당 TR 단가** (상품 페이지 요금 열이 비로그인 시 비어 있음)
- CODEF 정식버전의 **호출 단가** (요금계산기 종료, 가격정책 변경 중)
- 쿠콘 「대법원 법원경매정보 조회」의 **요금·제공범위·지역검색 가능 여부** 전부
- 세 곳 모두 **개인(비사업자) 명의 계약 가능 여부** — 공개 문서에 명시 없음. 하이픈 TR슬림은 "계약서 미작성 + 선불 비즈머니"라 상대적으로 진입 장벽이 낮아 보이나 확인 필요

### 사이트 직접 수집 — 차단됨

courtauction.go.kr 은 WebSquare 기반이고 내부는 평범한 JSON API 다.

- 검색: `POST /pgj/pgjsearch/searchControllerMain.on`
- 헤더: `SubmissionID: sbm_selectGdsDtlSrch`
- 요청: `dma_srchGdsDtlSrchInfo`(지역·용도 코드), `dma_pageInfo`(페이징)
- 응답: `dlt_srchResult` — `gamevalAmt`(감정가), `minmaePrice`(최저가),
  `yuchalCnt`(유찰), `maeGiil`(매각기일) 등

기술적으로는 어렵지 않다. 그러나 **화면 정의 XML 몇 개와 요청 두 번만으로
IP 가 차단됐다**:

```json
{"status":200,
 "message":"해당 IP는 비정상적인 접속으로 보안정책에의하여 차단되었습니다.",
 "data":{"ipcheck":false}}
```

약관 문구가 아니라 동작하는 보안 통제다. 이 차단이 영구인지 속도 기반인지는
모르지만, 그 경계를 찾는 작업 자체가 탐지 회피다. **만들지 않는다.**
차단당할 IP 가 앱 서버이자 봇 서버라는 실무적 위험도 있다.

### 채택한 방식 — 수동 등록

목록은 사용자가 사이트에서 직접 보고, 살 만한 물건만 앱에 옮겨 담는다.
`POST /api/listings/manual` (사건번호·소재지·감정가·최저가·면적·유찰·매각기일).

옮겨 담으면 공매 물건과 동일하게 처리된다 — 대출한도·취득세·ROI 계산,
지도 표시, 면적 필터. 경매라 중개보수 0, 명도비 경고 포함.
매각기일 당일에만 "입찰 가능"이 된다(기일입찰).

알림은 안 된다. 목록을 못 받으니 새 물건을 알 방법이 없다.
